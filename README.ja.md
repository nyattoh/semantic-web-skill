# semantic-web-skill

**デザインカンプから、意味のあるHTMLへ。ブリーフから、意味を備えたデザインカンプへ。**

Web制作で見た目と意味構造を切り離さず、セマンティックなHTMLソースコードを広めることを目指す公開プロジェクトです。デザインをコードに起こすときも、デザインから作るときも、コンテンツの意味、操作、アクセシビリティ、対象地域を早い段階から考えられるスキル集を育てます。

[クイックスタート](docs/quickstart.ja.md) · [静的比較例](examples/semantic-comparison/README.md) · [English](README.md) · [プロジェクト仕様](docs/product-spec.ja.md) · [現在の実装状況](docs/starter-status.md) · [貢献方法](CONTRIBUTING.md)

> **現在は設計資料とスキル草案をまとめたスターターです。** 完成済みの品質監査ツール、検証済みのエージェントスキル配布物、地域別ルール集ではありません。現在の制限は[実装状況](docs/starter-status.md)を確認してください。

## 目指す使い方

### 1. デザインカンプからHTMLへ

画像やデザインファイル、コンテンツ、技術条件、公開予定の地域をもとに、適切なHTML要素とコンテンツ構造を選びます。そのうえで実装し、実行した検査と未確認事項を記録します。見た目を再現するだけでなく、意味のあるソースコードを成果にすることが目標です。

### 2. ブリーフからデザインカンプへ

まだカンプがない場合は、目的、利用者、コンテンツ、ブランド、操作、公開地域を整理し、意味構造を意識したデザインを考えます。情報のまとまり、見出し、操作領域、状態、レスポンシブな変化をカンプの段階から考慮し、後のHTML実装につなげます。

### 3. 既存サイトをレビュー

コード、表示、操作を確認し、根拠と実際の検証結果を添えて改善点を示します。レビューの依頼だけで、コード変更や公開を許可されたことにはなりません。

この3つの経路は、採択済みの[設計判断 ADR 0003](docs/adr/0003-design-comp-centered-workflows.md)に沿っています。入口スキルには3経路を草案として反映しました。仕様書本文は保存版として維持し、変更内容を[実装状況](docs/starter-status.md)に記録しています。入力形式（画像、Figmaなど）やエージェントごとの実行方法、実動作は未確定・未検証です。

## 今このリポジトリを使う

現段階では、リポジトリ全体を設計資料として読む方法が中心です。[クイックスタートとコピー用プロンプト](docs/quickstart.ja.md)で経路を選び、[静的ソース比較例](examples/semantic-comparison/README.md)を試せます。インストールコマンドや自動実行機能はありません。

1. [現在の実装状況と未決定事項](docs/starter-status.md)を確認します。
2. [入口スキル](skills/semantic-web/SKILL.md)と、作業に関係する専門スキルを読みます。
3. 必要なら、リポジトリ全体をコーディングエージェントのコンテキストとして渡し、草案を設計ガイダンスとして使うよう依頼します。相対参照を使うため、単一ファイルや単一スキルだけを切り出さないでください。
4. 出力を実際に確認し、実行していない検査を合格扱いにしないよう依頼します。

試行用プロンプト：

> このリポジトリは未検証のスターターです。入口スキルと関係する参照資料を読み、草案として扱ってください。デザインカンプがあれば、その意味構造を整理してHTML/CSSの案または実装につなげてください。カンプがなくブリーフだけの場合は、利用環境で可能なら意味構造を反映したカンプを先に作り、情報のまとまり、見出し、操作部、状態、レスポンシブな振る舞いを示してください。カンプを作れない環境では、同じ内容を含む設計案を作ってください。実際に実行した検査、結果、未確認事項を分けて報告してください。スキルの読み込みだけを検証済みの品質保証として扱わないでください。

この試行方法は公式のインストール手順や、対応エージェントの保証ではありません。利用者の環境で確認した導入方法と対応状況だけを[互換性資料](docs/compatibility.md)に記録してください。

## 地域と言語

できるだけ多くの地域で使えることを目指します。地域固有の広告・法令・コンテンツ要件は、地域、商品、媒体、公開時期を明示したルールパックとして、信頼できる出典と人による確認範囲を含めて整備する方針です。現在、検証済みの地域パックはありません。未調査の地域への適合や、法令遵守を保証しません。英語・日本語の説明や、地域の一次資料に基づく貢献を歓迎します。

## 参加する

このプロジェクトは、利用者が試し、問題を報告し、ルール・例・翻訳を改善することで育つことを目指しています。GitHubで1,000スター以上は目標の一つですが、スターだけでなく、実際に使われること、再利用されること、継続的な改善につながることを重視します。

- [貢献ガイド](CONTRIBUTING.md)を読み、問題・根拠・適用範囲を添えて提案してください。
- ルール案には、出典、適用条件、合格・不合格・境界の例、誤検出の検討を含めてください。
- 翻訳では、対応する文書の制限や検証状況も揃えてください。
- 権利を確認していない第三者のデザイン、文章、顧客データは公開しないでください。

## 現在あるもの・ないもの

入口スキルと8つの専門スキルの草案、仕様書、参照ガイド、設計メモ、日英クイックスタート、3つの静的HTML比較例、限定した文書・fixture の検査があります。これらの検査は、スキルの動作やWeb品質を検証するものではありません。

実行可能な監査ルール、JSONスキーマ、製品の実動作テストランナー、CI、インストーラー、実動作を検証したデモ、検証済みの地域パックは未実装です。対応エージェント・ブラウザー・実機も検証していません。アクセシビリティ適合、検索順位、AI検索での引用、法令適合を保証しません。
