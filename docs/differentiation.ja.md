# 差別化と普及の方針

調査日: 2026-10-09 JST。[公開Skill比較](research/skill-comparison.ja.md)は7リポジトリの代表ファイルを固定コミットで比較した資料です。利用実績・生成品質・競合の導入動作は測定していません。

## 推奨する軸

**意味の設計 → カンプ → HTML → 操作と確認の対応を、人が追えるSkillにする。**

ネイティブHTML、アクセシビリティ、カンプを先に作ること、証拠の区別は公開Skillにもあります。本件の差別化候補は、同じコンテンツについて「どんな意味だからこの要素か」「どの状態を設計したか」「何を実際に確認したか」を、小さな通しの例と短い使い方で辿れるようにすることです。これは調査に基づく提案で、独占的な機能や優位性の実証ではありません。

例えば[frontend-a11y](https://github.com/mikemai2awesome/agent-skills/blob/b225980138789535683bf4cf17b6871f10c188ce/skills/frontend-a11y/SKILL.md)はネイティブ操作を具体化し、[web-quality-audit](https://github.com/addyosmani/web-quality-skills/blob/afa8da942115f2961fdbfa80807ea0b232ff6c00/skills/web-quality-audit/SKILL.md)は実測と推測を区別します。[Impeccable](https://github.com/pbakaus/impeccable/blob/30cdd375d1acd5dc3d3e31e1eeb3e83ec518002f/README.md)にもカンプを先に作る経路があります。これらの確認済み共通点を「競合にない」と宣伝しません。

## 補完する弱点と成果物

| AIへ任せる時のリスク | Skillで用意する手順 | 人が確認する成果 |
|---|---|---|
| 見た目から操作の目的を決めてしまう | 移動・操作・値入力・不明を内容から分ける | 実URLのリンク、明示した種類のボタン、ラベル、未決事項 |
| 似たカードを全て同じ構造にする | 同じ集合か、独立した領域かを確認する | 根拠付きlist/table/section判断、レイアウトだけのdivの許容例 |
| 送信中・失敗時の操作が抜ける | idle/submitting/success/errorの状態を設計する | 表示、通知、focus、値の保持、再試行と未実装endpointの境界 |
| スクリーンショットだけで良いと判断する | DOM・読み順・キーボード・状態を別に確認する | 幅ごとの見た目とDOM/操作順の記録、実施していない検査 |
| 意味判断と標準適合を混同する | 標準の要求・推奨・記述、プロジェクト慣習、人の判断を分ける | 出典、適用条件、観察、未検証を持つ所見 |

これは一般的なWeb実装で防ぎたい故障も含む分類です。AI生成サイトでの発生率や、Skill導入での改善率は今回測定していません。

## 普及の順番

1. **初回の結果を小さくする。** 初めての人が[短い使い方](quickstart.ja.md)で一つの部品を依頼し、意味の表とコードを読めるようにする。まず全ルールを暗記させない。
2. **同じ内容の比較を見せる。** [静的教材](../examples/semantic-comparison/README.md)の不適切な例・修正例・判断が変わる境界例を紹介する。見た目やdiv数を品質点数にしない。
3. **本当に実行した通しの参照例を育てる。** 同じ入力、ガイダンス版、モデル/host条件でblueprint→HTML→DOM/keyboard検証を記録する。静的教材だけでこの段階を達成済みとしない。元の失敗も残す。
4. **導入の依存関係を減らす。** 次の候補は必要な参照を同梱した配布物と一つのhostでの実呼出し検証。実行後にだけ対応host/版/制約を[互換性資料](compatibility.md)へ追加する。インストールしただけで生成品質を保証しない。
5. **参加しやすい貢献を用意する。** 一つの意味判断、境界例、出典、試した環境・失敗を小さなPRにできるよう[貢献ガイド](../CONTRIBUTING.md)へ案内する。日本語・英国英語を揃え、他言語の資料には検証状況も付ける。
6. **伝える単位を揃える。** README、記事、動画には「どの入力から何を判断したか」を示す。宣伝資料はSkillのソースと分けて保存し、未実装機能を機能一覧へ入れない。

## 成果の見方

GitHub 1,000スターは到達目標の一つ。使い方を理解できた人、一つの部品を試した人、再利用・問題報告・境界例の貢献・検証済みhost記録を、実際に観察した範囲で追います。数値の目標値、現在の利用者数、改善効果は調査していないため掲載しません。
